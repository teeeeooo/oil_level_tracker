# 배포 — 정한 것과 배포판 만드는 방법 (P-2b)

**상태:** 완료(2026-11-03). 배포판 2.0.0을 받아들였다. 커밋은 `11e4745`(태그
`v2.0.0`)이고, ZIP의 SHA-256은 `f1580dda…69e67`이다
([재확인 결과](../60-evidence/2026-11-03-p2b-release-recheck-windows-result.md)).
ZIP은 워크스테이션의 `C:\0.Coding\0.Release\`에 있다. 공유 폴더에 두고
검사자에게 알리는 일은 사용자가 한다(아래 "배포판 만들기" 7).

첫 Windows 확인([요청](2026-11-03-p2b-release-windows-request.md),
[결과](../60-evidence/2026-11-03-p2b-release-windows-result.md))은 R 한 줄만
남기고 모두 통과했다:
- 워크스테이션에서 ZIP을 만들었다;
- 최저 사양 PC에서 설치 안내만 보고 설치했다;
- 설명서가 Edge로 열렸다.

R은 검사 목록 원문이 전달되지 않아 판정하지 못했다.

사용자가 편집기 도움말을 줄여 달라고 했고, 2.0.0에 넣기로 했다(`11e4745`).
그래서 2.0.0 ZIP을 다시 만들어, R 보충과 함께 워크스테이션에서
[재확인](2026-11-03-p2b-release-recheck-windows-request.md)했다. 모든 항목이
통과했다.

- **배포판:** `OilLevelTracker-<버전>.zip` 하나.
  - 안에는 앱 폴더 `OilLevelTracker\`와 `설치 안내.html`이 나란히 있다.
  - Windows 워크스테이션에서 `scripts/build_package.py --release`로 만든다.
- **설치 안내 원본:** `packaging/install-guide.html`.
  - 설치 방법, 데이터 위치, 새 버전으로 바꾸기, 문제 보고, 이번 버전에서
    바뀐 것을 한 쪽에 담는다.
  - 만들 때 설명서 스타일을 안에 넣고 버전을 채워 파일 하나로 만든다.
- **함께 나가는 것:**
  - 소개 영상(Git 밖);
  - 사용 설명서 파일 하나(`OilLevelTracker-<버전>-사용설명서.html`).
    `scripts/make_manual_file.py`로 만든다.

## 정한 것 (사용자 인터뷰, 2026-11-03)

- **버전:** 2.0.0. 코드와 문서가 이미 v2로 부른다. 이후 수정은 2.0.1,
  기능 추가는 2.1.0으로 올린다.
- **형태:** 폴더 ZIP. V2-5에서 두 PC가 모두 이 방식으로 돌았다.
  - 관리자 권한과 설치 프로그램이 필요 없다.
  - 업데이트는 앱 폴더를 바꿔 끼우면 된다. 데이터는 문서 폴더에 있다.
- **전달과 설치:** 사용자가 ZIP을 사내 공유 폴더에 두면, 검사자가 설치
  안내를 보고 자기 PC에 직접 설치한다.
- **배포물 세 가지** (사용자, 2026-11-03, 인수 뒤): ZIP, 소개 영상, 사용
  설명서 HTML 파일 하나.
  - 검사자는 앱에서 F1을 눌러 설명서를 찾아보지 않는다. 그래서 설명서를
    따로 연다.
  - 설치 안내는 ZIP 안에 있으므로 따로 내지 않는다.
- **소개 영상:** 앱과 따로 공유한다.
  - 패키지에 넣지 않는다. 음악이 Suno 무료 계정으로 만든 부서 내부
    공유용 곡이다.
  - 저장소가 공개이므로 Git에도 올리지 않는다.
- **설치 안내와 변경 사항:** ZIP 맨 위에 HTML 한 쪽(`설치 안내.html`).
  릴리스 노트는 이 쪽의 "바뀐 것" 절이다.
- **설치 위치:** 검사자가 고른다. 안내에는 예시(`C:\Apps`)만 든다.
  네트워크 드라이브와 OneDrive로 동기화되는 폴더는 피하라고 적는다.
- **버전 표시:**
  - F1 도움말 창 아래에 "버전 2.0.0"을 보인다.
  - 보고서 1쪽 제목 아래에 만든 앱의 버전("Oil Level Tracker 2.0.0")을
    넣는다(Product SSOT §7).
- **편집기 도움말 줄이기** (사용자, 2026-11-03, Windows 실행 소감): 2.0.0에
  넣는다.
  - 모든 키와 마우스 동작을 남기고, 각각 한 줄로 쓴다.
  - 자세한 설명은 설명서에 맡긴다(DESIGN.md §4 "Help").
  - 앞 ZIP(`920dfbef…`)은 배포하지 않는다.
- **문제 보고:** "배포 담당자"에게 직접 알린다. 화면 캡처, 앱 버전, 검사
  이름, `app.log`를 함께 보내 달라고 적는다.
  - 처음에는 담당자의 이름과 ID를 적기로 했다.
  - 저장소가 공개라서 "배포 담당자"로만 적기로 바꿨다(사용자,
    2026-11-03).
  - 이름과 연락처는 사용자가 공유 폴더나 메신저로 따로 알린다.

## 에이전트가 정한 것

- **ZIP의 구성:**
  - 맨 위에 `설치 안내.html`과 `OilLevelTracker\`만 둔다. 그래서 "모두
    압축 풀기"로 고른 위치에 둘이 함께 생긴다.
  - 앱 폴더 이름에는 버전을 넣지 않는다. 같은 자리에 새 폴더를 두면
    바로 가기를 그대로 쓸 수 있다.
  - 설치 안내 파일 이름은 한글이다. ZIP에는 UTF-8 표시와 함께 저장한다.
    Windows 탐색기에서 이름이 바르게 보이는지는 Windows에서 확인한다.
- **설치 안내의 모양:** 설명서와 같은 스타일(`tokens.css`, `manual.css`)을
  파일 안에 넣는다. ZIP 안에서 바로 열어도 깨지지 않는다. 목차 없이 한 단으로
  쓴다(DESIGN.md §5 "Install guide").
- **설명서 파일 하나:**
  - 앱에 든 설명서와 내용이 같다.
  - 스타일과 스크립트는 파일 안에 넣는다. 그림 32개와 클립 6개는 base64로
    넣는다(2.0.0에서 약 2.7 MB).
  - 다른 파일을 읽지 않으므로 메신저나 메일로 보내도, 어디에 저장해도 두 번
    눌러 열린다.
  - 파일 이름에는 버전을 넣는다.
- **설명서 링크:** 설치 안내에서 앱 폴더 안의 설명서
  (`OilLevelTracker/_internal/oil_tracker/web/manual/index.html`)로 바로
  간다. 대상이 없으면 `--release`가 ZIP을 만들지 않는다.
- **exe 파일 속성:** 속성 → 자세히에 제품 이름과 버전(2.0.0)이 보이도록
  버전 리소스를 넣는다(`packaging/OilLevelTracker.spec`). 버전은
  `pyproject.toml` 하나에서 읽는다. 코드의 `__version__`이 이 값과 같은지는
  `tests/test_package.py`가 확인한다.
- **버전 연결:** 버전은 `bootstrap.py`가 HTTP 어댑터(`GET /api/about`)와
  보고서 어댑터에 넘긴다. 아키텍처 규칙상 어댑터가 패키지 루트를 직접 읽지
  않는다.
- **서명:** 코드 서명 인증서가 없다. 처음 실행할 때 "Windows의 PC 보호"
  창이 뜰 수 있으므로, 설치 안내에 "추가 정보 → 실행"을 적었다.
- **GitHub 릴리스는 만들지 않는다.** 저장소가 공개이고 배포는 공유 폴더로
  한다. Windows에서 받아들인 커밋에 Git 태그 `v2.0.0`만 붙인다.
- **설명서:**
  - 머리말을 "버전 2.0.0"으로 고쳤다.
  - 9장에 "여기에 없는 문제가 생겼다"(배포 담당자에게 알리기)를 더했다.
  - 보고서 그림은 부제에 버전이 들어가서 다시 찍었다. 나머지 그림은
    그대로다.

## 배포판 만들기 (버전마다)

1. **버전:** `pyproject.toml`의 `version`과
   `src/oil_tracker/__init__.py`의 `__version__`을 같이 올린다.
2. **바뀐 것:** `packaging/install-guide.html`의 "바뀐 것" 절을 새로 쓴다.
   - 무엇이 나아졌고 무엇을 고쳤는지 검사자 말로 쓴다.
   - 알려진 제한이 바뀌었으면 그것도 고친다.
3. **설명서:** 화면이 바뀌었으면 설명서 그림을 다시 찍는다
   ([user-manual.md](user-manual.md)). 머리말의 버전도 고친다.
4. **Windows 워크스테이션:**
   `python scripts/build_package.py --release`를 실행한다.
   - `package=PASS`여야 한다.
   - `zip=` 줄에 ZIP의 위치, 항목 수, 크기, SHA-256이 나온다.
5. **확인:** ZIP을 새 폴더에 풀어 실행해 본다. 도움말의 버전과 설치 안내도
   확인한다.
6. **사용 설명서 파일:** `python scripts/make_manual_file.py`를 실행한다.
   - 빌드가 필요 없어서 Mac에서도 Windows에서도 된다.
   - `build/release/OilLevelTracker-<버전>-사용설명서.html`이 생긴다.
   - 한 번 열어 그림과 클립을 확인한다.
7. **전달:** ZIP, 소개 영상, 사용 설명서 파일을 공유 폴더에 두고 검사자에게
   알린다.
   - 설치 안내는 ZIP 안에 있으므로, 알림에는 그 안내를 여는 법만 적는다.
   - 이름과 연락처도 이때 함께 알린다.

   예:
   > 공유 폴더의 `OilLevelTracker-2.0.0.zip`을 내 PC로 복사한 뒤 두 번
   > 눌러 열고, 안의 "설치 안내.html"을 따라 설치해 주세요. 사용법은 함께
   > 둔 "OilLevelTracker-2.0.0-사용설명서.html"과 소개 영상을 보세요. 문제가
   > 생기면 배포 담당자(이름, 연락처)에게 알려 주세요.
8. **태그:** 받아들인 커밋에 `v<버전>` 태그를 붙여 올린다.

## 확인한 것 (macOS, 2026-11-03)

- 전체 테스트 290개가 통과했다(새로 5개; 보고서·제출·도움말 smoke 테스트에 버전 확인 추가).
- macOS 한 폴더 빌드에 `--release`를 붙였다:
  - `version=2.0.0`, 280개 파일, 143.9 MB, `package=PASS`;
  - ZIP 281개 항목, 59.1 MB.
- ZIP을 풀어 Chrome으로 설치 안내를 열었다:
  - 스타일이 적용되고 콘솔 오류가 없다;
  - "사용 설명서" 링크로 앱 폴더 안의 설명서가 열린다.
- 도움말 창 아래에 "버전 2.0.0"이 "닫기" 왼쪽에 보인다(smoke 스크린샷).
- API로 제출한 보고서 1쪽에 "Oil Level Tracker 2.0.0"이 들어간다.
- **설명서 파일 하나** (인수 뒤 추가):
  - 이 파일만 빈 폴더에 두고 Chrome으로 열었다;
  - 페이지 말고는 아무 파일도 읽지 않았다;
  - 그림 33개가 모두 보이고, 클립 6개가 모두 읽힌다;
  - 콘솔 오류가 없다;
  - 클립 재생, 그림 확대, 목차 표시가 원래 설명서와 같다.

  Windows의 Edge로는 열어 보지 않았다. Edge도 Chrome과 같은 엔진이고, 이
  파일은 다른 파일을 읽지 않는다.
- **Windows에서 볼 것:**
  - 테스트 수와 빌드;
  - exe 속성의 버전;
  - ZIP 안 한글 파일 이름;
  - 검사자 PC에서 설치 안내만 보고 설치하기;
  - 설명서가 Edge로 열리는지(P-2에서 넘긴 확인);
  - 예전 빌드로 만든 데이터가 새 버전에서 열리는지;
  - 보고서의 버전.
