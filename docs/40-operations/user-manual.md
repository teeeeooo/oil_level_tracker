# 사용 설명서 — 정한 것과 만드는 방법 (P-2)

**상태:** 완료. 사용자가 첫 판을 확정했다(2026-11-03). 바꾼 것은 글 두 곳뿐이다(아래 "검토").

- **설명서:** `src/oil_tracker/web/manual/index.html`. 앱과 함께 배포하는
  오프라인 HTML 한 쪽이다. 글은 이 파일에 직접 쓴다.
- **스크린샷과 클립:** `scripts/render_manual.py`가 실제 앱을 조작해 찍는다.
- **여는 곳:** 앱의 F1 도움말 창에 있는 "사용 설명서" 단추. 보고서처럼 기본
  브라우저(Windows에서는 Edge)로 연다.

## 정한 것 (사용자 인터뷰, 2026-11-03)

- **읽는 사람:** 앱을 처음 쓰는 검사자. 앱을 열고 Recipe를 만들고, 분석,
  편집, 제출, 보고서까지 한 번에 따라 할 수 있게 쓴다.
- **형식:** 오프라인 HTML. 앱과 함께 배포하고 F1 도움말 창에서 연다.
- **언어:** 한국어만. 앱 화면이 한국어다.
- **화면:** 단계마다 스크린샷을 넣는다. 움직임을 봐야 하는 조작(그리기, 범위
  지우기, 점 잇기 같은 것)만 몇 초짜리 반복 클립으로 보여 준다.
- **예시 영상:** sample7(유리컵).
  - 소개 영상과 같은 예시이고, Mac에서 자동으로 찍을 수 있어 앱이 바뀌면
    다시 찍기 쉽다.
  - Glass는 소개 영상과 같다(컵 윗부분을 뺀다).
- **범위:** 처음부터 제출까지 따라 하는 "빠른 시작" 다음에, 작업별 장에서
  모든 기능을 다룬다. 단축키 목록은 F1 도움말에 맡긴다.

## 검토 (사용자, 2026-11-03)

- 첫 판은 이상 없이 확정한다.
- 설명 글에서는 "우유" 대신 **"유체"**라고 쓴다. 고친 곳은 배경 제거 보기
  그림 설명과 6장 첫 그림 설명이다. 예시 영상을 소개하는 첫머리 문장("유리컵에
  우유를 붓는 예시 영상")은 그대로 둔다.
- 찍다가 본 알림 문구 겹침(아래)도 이번에 고친다.

## 에이전트가 정한 것

- **자리:**
  - 설명서는 `web/manual/`에 둔다. 패키지 설정이 `web/`을 통째로 넣으므로
    따로 손댈 것이 없다.
  - 여는 일은 use case `application/manual.py`가 맡는다: 배포된 파일을
    `Desktop.open_file`로 연다.
  - 경로: 도움말 단추 → `POST /api/manual/open`.
  - 도움말 창은 전처럼 "닫기"에 초점을 둔다.
- **화면 크기:** 앱의 최소 창(1280 × 800)으로 찍는다. 1440 폭에서 찍은
  화면을 설명서 폭으로 줄이면 글자가 너무 작았다.
- **번호 표시:** 그림의 부분을 설명할 때는 대상에 테두리를 두르고, 번호는
  대상 바깥에 둔다. 그림 아래 목록이 같은 번호를 쓴다. 판정 칸 그림은 번호
  자리를 내려고 찍는 동안만 왼쪽 여백을 넓힌다.
- **찍을 때만 바꾸는 것:**
  - 임시 데이터 폴더 경로는 Windows에서 보일 경로로 바꿔 찍는다:
    `C:\Users\사용자\Documents\OilLevelTracker`, 영상은
    `C:\Users\사용자\Videos\`.
  - 몇 초 뒤 사라지는 알림은 지우고 찍는다.
  - 영상 파일 이름은 `예시_유리컵.mp4`.
- **빼거나 바꾼 것:**
  - 반복 붙여넣기 화면은 넣지 않았다. 예시 영상에 반복 패턴이 없어 오히려
    헷갈린다. 글과 복사 칸 그림으로 설명한다.
  - 잡아끌기 클립은 끌기 폭을 30초에서 10초로 줄인 뒤 한 곳을 끌어
    올린다. 30초 폭으로 끌었더니 선 전체가 올라가 FULL에 붙었다.
- **디자인:** DESIGN.md §3에 "Body 1 Reading"(14/22)을, §4 도움말과 §5에
  설명서 배치를 더했다.

## 목차

1. 시작하기 전에: 앱이 하는 일과 검사자가 하는 일, 쓰는 말, 첫 화면, 데이터가
   있는 곳
2. 빠른 시작: 여섯 단계 카드
3. Recipe 만들기: 목록, 새 Recipe, Glass와 0선, 판정 규칙, 저장
4. 검사 시작하기: 영상과 Recipe 고르기, 분석 설정, 분석
5. 편집기 둘러보기: 화면 구성, 보기 바꾸기, 배경 제거 보기, 크게 보기
6. 선 고치기: 그릴 선, 범위로 지우기, 연필, 점 잇기, 잡아끌기, 선택,
   FULL·EMPTY, 판단 불가, 복사와 붙여넣기, 메모, 기동 표시·빈 구간·저장, 다시
   분석
7. 판정 확인하기: 판정 읽기, 직접 판정, "이 Glass 확인"
8. 제출과 보고서: 제출, 제출한 버전, 보고서, 고쳐서 다시 제출
9. 문제가 생겼을 때

글은 F1 도움말 표, Product SSOT §3–§7, 실제 화면의 문구를 따랐다.

## 만드는 방법

```bash
PYTHONPATH=src .venv/bin/python scripts/render_manual.py
```

약 2분 걸린다. `--stop STAGE`로 중간 단계까지만 찍을 수 있다.

**만드는 과정:**
- 이 폴더의 코드로 앱을 임시 데이터 폴더에서 띄우고, Chrome(1280 × 800,
  2배 화소)에서 검사 하나를 처음부터 끝까지 진행한다.
- 진행 순서는 Recipe, 분석 설정과 분석, 편집기 둘러보기, 초안 바로잡기,
  나머지 도구, 판정과 확인, 제출과 보고서, 원본 영상 경고다. 판정 단계 전에는
  저장하고 다시 열어, 앞 단계의 복사 칸과 알림을 지운다.
- 스크린샷은 `img/<이름>.webp`로 저장한다. CSS 화소당 1.5화소이고, 빠른
  시작 썸네일은 `-thumb`(0.75화소)다.
- 클립은 `clips/<이름>.mp4`로 저장한다. H.264이고 소리가 없으며, 찍은 화소
  그대로이거나 폭 1920 이하다.
  - 녹화는 소개 영상의 `render_intro.Clip`을 쓴다. 한 프레임마다 스크린샷을
    찍는다. 이번에 `Clip`에 저장 폴더와 찍을 영역을 넘기는 인자를 더했다.
  - 포인터, 누르는 동안의 고리, 누른 키는 앱 페이지 위에 그린다. 그리는 층은
    팝오버라서 열린 대화상자 위에도 보인다.
  - 포인터 모양은 그 자리의 CSS 커서를 따른다(화살표, 십자, 양방향 화살표,
    이동).

**바뀌면 다시 찍는다:** 앱 화면이 바뀌면 스크립트를 다시 돌린다. 그림 크기가
달라졌으면 `index.html`의 `width`/`height`도 고친다. `tests/test_manual.py`가
확인하는 것:
- 설명서가 쓰는 파일이 모두 있다;
- 쓰지 않는 그림이 없다;
- 목차와 안쪽 링크가 모두 이어진다;
- 파일에서 열려도 동작한다(모듈 스크립트와 fetch가 없다).

## 확인한 것 (macOS, 2026-11-03)

- 전체 테스트 285개가 통과했다(새로 5개, 도움말 smoke에 단추 확인 추가).
- Chrome에서 설명서를 파일로 열었다:
  - 깨진 그림과 콘솔 오류가 없다;
  - 클립 6개가 모두 읽힌다;
  - 화면에 들어온 클립만 재생된다.
- 실제 앱 페이지에서 F1 → "사용 설명서"를 누르면 배포된
  `web/manual/index.html`이 열린다(브라우저를 띄우는 함수만 바꿔 확인).
- **Windows에서 볼 것:** Windows 빌드에서 Edge로 열리는지. 보고서와 같은
  `os.startfile` 경로다. 다음 마일스톤(P-2b, Windows 패키징과 배포 준비)의
  빌드에서 함께 본다.

## 찍다가 본 앱의 작은 문제 (고침)

- **증상:** 원본 영상이 없을 때 편집기 알림이 "영상을 열 수 없습니다: 영상을
  열 수 없습니다: 예시_유리컵.mp4"로 앞말이 겹쳤다.
- **원인:** 서버가 이미 "영상을 열 수 없습니다: …"처럼 완결된 문장을 보내는데,
  화면이 그 앞에 같은 말을 붙였다. 같은 일이 세 곳에 있었다: 편집기, 원본 영상
  창, 분석 설정.
- **고침:** 세 곳 모두 서버 문장을 그대로 보이고, 서버 문장이 없을 때만
  화면의 말을 쓴다(사용자, 2026-11-03: 이번에 고친다).
- **확인:** 편집기 smoke 테스트에 영상이 없어진 경우를 더했다. 고치기 전
  코드에서는 실패하고 고친 뒤에는 통과한다. 원본 영상 창과 분석 설정은 같은
  한 줄 변경이라 따로 띄워 보지 않았다.
- 설명서 그림은 툴바 아래 경고 줄만 잘라 썼으므로 다시 찍지 않는다.
