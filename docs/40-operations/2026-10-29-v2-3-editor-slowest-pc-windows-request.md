# Windows 요청: 최저 사양 PC 편집기 측정 (A5·A6) (2026-10-29)

> 이 문서는 **사용자가 최저 사양급 PC의 터미널에서 직접** 실행하는 절차다. 그 PC에는 코딩 에이전트가 없다.
> - 명령 3줄을 차례로 붙여넣으면 스크립트가 SPL#1을 분석한 뒤, Edge 창을 열어 편집기를 **스스로** 조작하며 잰다.
>   마지막으로 분석의 중앙값 계산 방식들을 견준다. 결과는 마크다운 파일로 저장되고 화면에도 출력된다.
> - **판단 기준**은 아래 "판단 기준" 절에 있고, 실행 전에 고정됐다.
> - 결과 파일의 **내용 전체**를 돌려주면 된다.

## 무엇을 확인하나

인수 기준 A5와 A6은 최저 사양급 PC(Intel Xeon E5-1620 v3, RAM 16GB, NVIDIA Quadro K620)에서도 지켜야 한다
(Product SSOT §2). 편집기의 핵심(잡아끌기, 연필, 범위 지우기, 영상)이 생겼으므로, 나머지 도구를 만들기 전에 잰다.

- **A5:** 68분짜리 SPL#1(샘플 8,210개)에서 선을 끄는 동안 다시 그리기가 중앙값 16ms, 최대 50ms 안이어야 한다.
  spike는 워크스테이션에서 샘플 2,053개로 13.4 / 30ms였다. 이번에는 샘플이 4배다.
- **A6:** 멈춘 화면의 정확한 프레임이 중앙값 100ms 안에 나오고, 1배 재생이 끊기지 않아야 한다.
  SPL#1의 코덱도 함께 확인한다. 편집기의 영상은 Edge(WebView2와 같은 엔진)가 재생할 수 있는 코덱이어야 한다.
- **A4 준비 (중앙값 비교):** 분석 시간(A4)은 이 PC에서 180초 기준에 10초 남짓 여유밖에 없다. 분석은 Glass 띠의
  줄마다 중앙값을 구하는데(지금은 `int16` 정렬), 어느 계산 방식이 빠른지는 CPU에 따라 다르다(NumPy가 SIMD로
  정렬하는 값의 종류가 CPU마다 다르다). 그래서 여러 방식을 이 PC에서 견준다. 모든 방식은 앱과 **똑같은 값**을 내야 한다.
- 이번 측정은 앱 창(pywebview) 대신 **Microsoft Edge**에서 한다. 앱 창도 Edge의 엔진(WebView2)으로 그리므로,
  그 PC에 앱 창용 부품을 설치하지 않아도 된다. 패키지된 앱으로 하는 최종 판정은 V2-5에서 한다.
- 스크립트는 결과 파일 하나와 측정용 데이터 폴더(`a5a6-data-…`) 하나를 쓴다. 영상과 Recipe는 읽기만 한다.

## 1. 준비 [사용자]

1. **Python**: PowerShell에서 `py -0`을 실행하면 설치된 버전 목록이 나온다. `3.14`가 있으면 3절 명령 그대로,
   지난번처럼 `3.15`만 있으면 3절 첫 줄의 `-3.14`를 `-3.15`로 바꾼다.
2. **인터넷 연결**: 3절의 두 번째 명령이 OpenCV, NumPy, Playwright(Edge를 조작하는 도구)를 받는다.
   인터넷이 없으면 5절을 따른다. Edge는 Windows에 이미 있으므로 따로 받지 않는다.
3. **파일 2개**: 지난번(A4 측정)에 `C:\a4\`에 둔 두 파일을 그대로 쓴다. 지웠다면 워크스테이션에서 다시 복사한다.
   네트워크 드라이브에 두지 않는다.
   - `SPL#1_Heating_coldstart.mp4` (683,165,477 bytes)
   - `SPL#1_test1_607bccb.recipe.json`
4. **소스**: 아래 주소의 ZIP을 받아 압축을 푼다. 커밋 하나로 고정된 코드다.
   `https://github.com/teeeeooo/oil_level_tracker/archive/8a96b223c11e1eddb6b7d86b12a6a18c30c21642.zip`
5. 측정 중에는 **다른 프로그램을 닫는다.**

## 2. PowerShell 열기 [사용자]

압축을 푼 폴더(`oil_level_tracker-8a96b223…`, 안에 `scripts`와 `src` 폴더가 있다)를 탐색기로 열고,
주소창에 `powershell`을 입력한 뒤 Enter를 누른다. 그 폴더에서 PowerShell이 열린다.

## 3. 실행 [사용자]

아래 3줄을 한 줄씩 붙여넣고 Enter를 누른다. 마지막 줄의 두 경로는 파일을 둔 실제 위치로 바꾼다
(`#`이 든 경로라 큰따옴표는 그대로 둔다).

```powershell
py -3.14 -m venv .venv-measure
.venv-measure\Scripts\python -m pip install opencv-python-headless==4.14.0.94 numpy==2.5.4 playwright==1.64.1
.venv-measure\Scripts\python scripts\measure_editor.py --video "C:\a4\SPL#1_Heating_coldstart.mp4" --recipe "C:\a4\SPL#1_test1_607bccb.recipe.json"
```

- 화면에 `[1/5]`부터 `[5/5]`까지 단계가 나온다.
- `[3/5]` 분석은 약 3분 걸리고, 30초마다 `progress` 줄이 나온다.
- `[4/5]`에서 **Edge 창이 열리고 저절로 움직인다**(선 그리기, 끌기, 확대, 프레임 넘기기, 60초 재생). 약 5분 걸린다.
  - 이 동안 **마우스와 키보드를 건드리지 않는다.** 마우스가 창 위에서 움직이면 측정에 섞인다.
  - Edge 창을 **최소화하거나 다른 창으로 가리지 않는다.** 가려진 창은 브라우저가 느리게 그린다.
  - 창이 화면보다 커도 괜찮다. 끝나면 창은 저절로 닫힌다.
- `[5/5]` 중앙값 비교는 창 없이 약 1분 걸린다. 이 동안에도 다른 프로그램을 쓰지 않는다.
- 끝나면 결과 표가 출력되고, `결과 파일: …\a5a6-editor-YYYYMMDD-HHMM.md` 경로가 나온다.
  그 아래 줄의 `a5a6-data-…` 폴더는 측정용 검사 데이터라 지워도 된다.
- 중간에 오류가 나면 스크립트는 오류 내용을 결과 파일에 적고 끝난다.

## 4. 돌려줄 것 [사용자]

- **결과 파일의 내용 전체.** 파일을 USB로 옮겨 붙여넣거나, 결과 표가 보이는 화면을 사진으로 찍는다.
- **메모:** 모니터 해상도, 측정 중 Edge 창이 계속 보였는지, 닫지 못한 프로그램, 그 밖에 특이한 점
  (Edge 창이 끊겨 보였는지, 재생이 멈칫했는지 등 눈으로 본 것).
- 2번째 명령(`pip install`)이 실패했다면 그 출력의 마지막 20줄.

## 5. 인터넷이 없을 때 [사용자]

인터넷이 되는 PC(워크스테이션)에서 설치 파일을 받아 USB로 옮긴다. 마지막 `3.14`는 측정 PC에서 쓸 Python 버전에 맞춘다
(3.15면 `3.15`).

```powershell
py -3.14 -m pip download opencv-python-headless==4.14.0.94 numpy==2.5.4 playwright==1.64.1 --only-binary=:all: --platform win_amd64 --python-version 3.14 -d a5-wheels
```

`a5-wheels` 폴더를 측정 PC에 복사한 뒤, 3절의 두 번째 명령 대신 아래를 실행한다(경로는 실제 위치로).

```powershell
.venv-measure\Scripts\python -m pip install --no-index --find-links "C:\a4\a5-wheels" opencv-python-headless==4.14.0.94 numpy==2.5.4 playwright==1.64.1
```

## 6. 워크스테이션 (선택)

같은 ZIP으로 워크스테이션에서 3절을 한 번 더 실행하면 두 PC를 견줄 수 있다. 측정 PC 결과만으로도 판단은 된다.

## 판단 기준 (실행 전에 고정)

| ID | 조건 | 결정 |
|---|---|---|
| M1 | 결과 파일의 소스 줄이 `source=1da92bcf0279 files=54` | 소스가 맞다 |
| M2 | CPU 줄이 Xeon E5-1620 v3 또는 그와 비슷한 4코어 CPU | 최저 사양급 PC다 |
| M3 | 분석 줄에 `샘플 8210개` | SPL#1 전체를 편집했다 |
| A5 | A5 표 **전체** 줄의 중앙값이 **16ms 이하**이고 최대가 **50ms 이하** | 통과. 아니면 나머지 도구(7단계) 전에 그리기를 가볍게 만든다 |
| A5-f | 세 장면의 프레임 간격 중앙값이 모두 20ms 이하 | 화면 그리기도 따라온다. 넘으면 그리기(페인트) 쪽이 병목인지 살펴본다(기록만, A5 판정은 위 줄) |
| A6-s | 정확한 프레임(서버) 중앙값이 **100ms 이하** | 통과. 넘고 `<video>` 탐색 중앙값이 100ms 이하이면, 멈춘 화면을 `<video>`로 보여 주는 방식을 사용자와 정한다. 둘 다 넘으면 프레임 읽기를 빠르게 하는 작업을 먼저 한다 |
| A6-p | 재생 방식이 `<video>`이고, 진행이 60초 중 **59.0초 이상**, waiting·stalled **0**, 버린 프레임이 전체의 **1% 이하** | 통과 |
| A6-c | 재생 방식이 `frames (대체)` | Edge가 SPL#1의 코덱(결과의 `코덱` 줄)을 재생하지 못한다. 대책(코덱 확장, 변환 등)을 사용자와 정한다 |
| A4-m1 | 중앙값 표의 `출력`이 모두 `기준` 또는 `같음` | 모든 방식이 앱과 같은 값을 낸다. `다름`인 방식은 후보에서 뺀다(기록) |
| A4-m2 | `같음`인 방식 중 스레드 열의 배율이 가장 큰 방식이 **1.5 이상**이고, 맥락 패스 표에서 그 방식의 1회+2회가 지금 방식보다 크지 않다 | 그 방식을 앱의 분석에 넣는다(값이 같으므로 분석 결과는 바뀌지 않는다). 아니면 지금 방식을 유지한다 |
| — | 맥락 패스 표의 시간 차이 | 기록만: 2분 구간에서 줄어든 시간으로 68분 분석에서 줄어들 시간을 어림한다 |
| — | 분석 시간(앱 서버로) | 기록만: 어댑터만으로 잰 169.7초와 비교해 앱이 더하는 몫을 본다(V2-5 전 열린 항목) |
| — | 결과 파일 끝이 `오류: 없음` | 오류가 없다 |

- **다시 그리기**는 끄는 동안 선 층을 새로 만드는 데 걸린 시간이다(spike와 같은 잣대). **프레임 간격**은 그동안 화면이
  실제로 바뀐 간격이다. 60Hz 모니터에서는 16.7ms가 가장 짧다.
- 세 장면: 선 3개(Oil, Foam, 참조)를 연필로 처음부터 끝까지 그리기, 전체 보기에서 잡아끌기 8번, 10배 확대해 잡아끌기 8번.
  선이 모두 그려진 상태가 가장 무겁다.
